# F1 25 UDP Coverage And Engineering Logic Matrix

## Goal

Build a pit wall system where every feature is either:

1. Directly mapped from F1 25 UDP fields.
2. Deterministically calculated from UDP-derived state.
3. Generated by explicit rule-based interpretation when UDP does not provide direct values.

No random values are allowed in production race mode.

## 1) Direct UDP Mapping (1:1)

These fields must be consumed directly from packets and stored without synthetic generation.

- Car telemetry:
  - speed
  - throttle
  - brake
  - gear
  - rpm
  - drs
  - brake temperatures (4 corners)
  - tyre surface temperatures (4 corners)
  - tyre inner temperatures (4 corners)
  - engine temperature
- Lap data:
  - car position
  - current lap
  - current lap time
  - last lap time
  - pit status
  - delta to front
  - delta to race leader
  - penalties
  - warnings
- Car status:
  - fuel in tank
  - ERS store energy
  - visual tyre compound
  - tyre age laps
- Session/control:
  - session type
  - track id
  - weather id
  - safety car status
  - total laps
- Motion/minimap:
  - per-car world position x/z

## 2) Deterministic Calculations From UDP

These values are required for engineering decisions and must be explicitly calculated from direct UDP fields.

- Gap to player from lap delta-to-leader differences.
- Pace stability score from:
  - lap-time spread
  - consistency
  - tyre degradation impact
  - traffic compression
- Fuel risk from:
  - fuel remaining
  - estimated fuel per lap
  - laps remaining
- Strategy confidence from:
  - action score edge
  - data reliability
  - pace stability
- Undercut / overcut expected gain from forward simulation:
  - compare PIT_NOW / PIT_IN_2 vs STAY_OUT simulation time
- Pit window recommendation using:
  - tyre age/wear proxy
  - laps remaining
  - race control state
  - traffic model
- Event priority score from deterministic severity rules.

## 3) Rule-Based Generated Outputs (Not Directly In UDP)

These are not native UDP fields and must be generated by deterministic logic.

- Strategy guidance text:
  - PIT NOW, PIT IN 1, STAY OUT, SAVE, PUSH, HOLD
  - include rationale and score delta
- Event explanations:
  - map event codes + state transitions into operator-readable messages
- Radio-like operator log:
  - summarize strategic and control-state changes
  - include recommended action context
- Weather outlook:
  - near-term trend probability from current weather/control state
  - no random noise

## Current Implementation Decisions

- Random tyre temperatures were removed from UI and replaced with telemetry-derived tyre surface temperatures.
- Weather forecast view was changed from trigonometric/random simulation to deterministic trend projection.
- Lap packet decoding now ingests pit status, front/leader deltas, and warning/penalty fields.
- Telemetry packet decoding now ingests brake/tyre/engine temperatures.
- Leaderboard gap now uses decoded lap delta data first, with deterministic fallback when unavailable.
- Strategy engine now includes tyre age input and exposes undercut/overcut gains.

## Remaining Hard Requirements For Full Race-Engineer Grade

- Extend packet coverage to additional F1 25 packets as needed (participants, damage, session history, etc.).
- Add uncertainty-aware confidence intervals around strategy outputs.
- Add stronger event ontology (incident, safety car, tyre cliff onset, traffic trap).
- Implement scenario replay validation against recorded races.
- Add operator-facing explanation templates tied to strategy model internals.

## Acceptance Criteria

- No UI widget uses Math.random or non-deterministic synthetic values for race-critical data.
- Every displayed metric is tagged as direct UDP, derived deterministic, or rule-generated.
- System can answer: "Should we pit now?" with numerical basis:
  - expected gain/loss (s)
  - risk/confidence
  - key factors (tyre, traffic, pit loss, laps remaining)
